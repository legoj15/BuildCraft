###### Changes since 2026.2.0-br1:
- **Oil now generates as part of world generation proper, on every version.** Oil used to be placed as chunks *loaded*, a legacy approach where any slip past a chunk boundary could freeze the whole game — the source of a string of world-generation hangs (most recently with large biome mods on 1.21.1). Oil deposits are now built by a real world-generation feature inside the generation pipeline, where that failure is impossible by construction, so this class of freeze is gone for good rather than patched case-by-case. Existing worlds are unaffected: already-explored terrain keeps its oil, and newly explored terrain lines up seamlessly (deposit placement is seed-identical to before).
- **Fixed a world-generation freeze on the 1.21.1 build when playing with large biome mods (e.g. Biomes O'Plenty).** Creating or exploring into new terrain could hang the game with no crash and no log — you could still look around, but everything else stopped. Oil generation, which runs as chunks load, could reach into a neighbouring chunk that hadn't generated yet (to place oil or to sample the biome) and lock up the server thread forever. Oil placement and its biome checks now stay within already-generated chunks, so worlds generate smoothly. (The other builds weren't affected.)
- **Corrected the minimum NeoForge version each build advertises.** The 1.21.1 build now requires NeoForge 21.1.151+ — the release that added the menu API BuildCraft's spectator-safe GUIs depend on — so older NeoForge is cleanly refused at load ("update NeoForge") instead of installing and then breaking. The 1.21.10 build's floor was relaxed to 21.10.63 (it no longer needlessly rejects that build). The 26.1.x, 26.2 and 1.21.11 builds were already correct — the 26.1.x jar is verified to run on the entire 26.1 line.
