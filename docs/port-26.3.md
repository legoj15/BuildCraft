# BuildCraft 26.3 port plan

Agent-focused. Written 2026-10-19 on branch `claude/mod-port-26-3-fb417c`; baseline is scaffold commit `161f2dabe306261633b8c0a201eeaba5e4b13c14`. Nothing below is implemented: the 26.3 node reaches javac and fails.

Confidence tags: **verified** (read in `.neoforge-ref` sources, a jar, or a build log), **inferred** (deduced from verified facts), **unverified** (needs a run or an in-client look). Where an input claim was re-checked and found wrong, the text says so.

Shorthand: `REF` = `E:/GitHub/BuildCraft/.neoforge-ref` (a gitignored junction in this worktree to the main checkout's copy). Paths starting `src/` are relative to the worktree root. "26.3 branch" = code that must run only on the 26.3 node.

### How to compile the node

- Main code: `./gradlew :26.3:compileJava`. At the baseline it fails with **168 errors and 24 deprecation warnings**. The count is identical with `-Xmaxerrs 10000` and `-XDshould-stop.ifError=FLOW`, so every error is attribution-level. Code hidden behind the broken types, plus flow-phase errors, only appears as the first wave is fixed. Budget for a second wave (packet P12).
- Other nodes: `:26.2:compileJava`, `:26.1.2:compileJava`, `:1.21.11:compileJava`, `:1.21.10:compileJava`, `:1.21.1:compileJava`. Pass `--continue` so a failing 26.3 does not stop the rest.
- Tests: Gradle skips `:26.3:compileTestJava` while main fails. Test-side view without main: `./gradlew :26.3:compileTestJava -x :26.3:compileJava` (12,674 errors, about 97 percent cascade from missing main classes).
- Error caps: `build.gradle.kts` already sets `-Xmaxerrs 2000`, enough for main. Larger caps need the init script `build/port-26.3-maxerrs.init.gradle`, which lives in the gitignored `build/` and is lost on a clean; P0 promotes it into `scripts/`.
- Never run `stonecutter active` or the "Set active project" task inside a packet. It rewrites directive markers tree-wide, which would conflict across parallel packets. The 26.3 node compiled from its own processed sources while the active node stayed 26.1.2 through Wave 2; P15 then made 26.3 the active node in one commit of its own.
- Root `fullTestSuite` and `buildAndCollect` enumerate every subproject, so both include `:26.3` and fail until it compiles. Use per-node tasks meanwhile.
- Scaffold artifacts (gitignored, under `build/`): `port-26.3-compileJava.log`, `port-26.3-errors-compact.txt`, `port-26.3-clusters.json`, `port-26.3-compileTestJava.log`, `port-26.3-compileTestJava-nomain.log`.
- Reference sources: `REF/sources-26.3.0.95` (8,431 files, NeoForge plus vanilla classes), `REF/sources-26.2.0.93` for the diff baseline. `REF/vanilla-26.3` holds only `26.3.jar` (use `unzip -l` or javap). `INDEX.txt` lists `vanilla-26.2` and `vanilla-1.21.10`, which do not exist on disk; use the `sources-*` dirs.

## 5. Test-side impact

- **compileTestJava.** Blocked behind main. The no-main view shows 12,674 errors, almost all cascade. Genuine test-side clusters seen so far: t01 (3 files), c21 (`FakePlayerUtilTester:352,364`), c07 (`GateRecipeVariantTester:122-123`), the four `playerDestroy` callers below, and one `Ingredient#items()` deprecation at `DyedPipeTableDriftTester:103`. Expect more once main compiles.
- **`Block#playerDestroy`.** Now takes `ServerLevel` and `ServerPlayer`. ## 6. Work packets

### Execution protocol

- **File ownership is exclusive.** The lists below are disjoint by construction (checked with a script over the cluster JSON; zero overlaps; expected error reductions sum to exactly 168). A packet must not edit a file outside its list. If it must, it stops and reports to the orchestrator.
- **No packet edits `changelog.md`, `todos.md`, `AGENTS.md` or this doc.** Each returns one suggested changelog line and one delegation-log line; the orchestrator consolidates (changelog conflicts are the known merge hazard). Packets also never switch the Stonecutter active node.
- **Worktrees.** Each implementer gets its own sub-worktree cut from the port branch HEAD (verify the base SHA first: agent worktrees can cut behind HEAD), and the orchestrator cherry-picks the results in. Run `gradlew --stop` between heavy runs and before external reviews. A new worktree needs the `.neoforge-ref` junction (gitignored) for reading references.
- **Directive authoring.** The tree was in the 26.1.2 active-node state through Wave 2: `//? if <26.3` arms were live raw code and `//? if >=26.3` arms were wrapped in a block comment. Since P15 the tree is in the 26.3 state, so it is the other way round: `>=26.3` arms are live and `<26.3` arms are wrapped. Any prose comment goes inside the commented arm. Prefer a helper with one directive pair over many call-site pairs. If a shareable non-deprecated API exists, do not fork (AGENTS.md).
- **Gate A (every packet).** `./gradlew --continue :26.3:compileJava :26.2:compileJava :26.1.2:compileJava :1.21.11:compileJava :1.21.10:compileJava :1.21.1:compileJava`. Pass means: the five non-26.3 nodes succeed; the 26.3 log shows zero errors in the packet's files and the total falls by the packet's count (new errors may appear only in files the packet does not own, as second-wave exposure); no new warnings in the packet's files.
- **Gate B (packets that edit test sources: P6, P9).** Also `compileTestJava` on every non-26.3 node.
- **Review.** Each merged packet goes through `reviewer` (Haiku xhigh) plus at least one non-Anthropic lane via `opencode-fanout`, per the global ladder. Test running and log babysitting go to Haiku or the free lab lanes.
- **Escalation is mechanical:** one failed or unverified attempt moves a packet from `impl` to `impl-opus`; no retry at the same tier.

1. **B0 persistence break.** Silent loss of every stored block state across the 26.2 to 26.3 upgrade, if P11 is skipped. Highest impact; only the upgrade smoke proves it fixed.
2. **Second-wave compile errors.** 168 is the attribution-level count only. Render code (submit collectors, pipelines) is the likeliest source; the test-side count is 12,674 with a small genuine core. P12 exists for this.
3. **OIT runtime crash (B1).** Possible `IllegalStateException` for BC RenderTypes without an OIT pipeline set. Cannot be seen without a client.

- **Shard tint channel order (B11).** `FluidShardTintSource` decodes ARGB pixels as ABGR on 1.21.10 and later, so red and blue are swapped for coloured still sprites on the 26.2 primary today. Only 1.21.1 returns ABGR. Fix separately via `NativeImagePixels.getArgb` and an ARGB decode, after settling whether the animated-frame offset matters. The c17 directive does not fix it, on purpose.
- **Stale comments** that go wrong after the port: `MutableQuad` (26.1 wording), `BCLibRenderTypes:61` (says the default depth state is less-than-or-equal; it is greater-than-or-equal), `CraftingUtil:100-102` and `AssemblyRecipeCollector:81` (mention `FUEL_VALUES`), `BCEnergyFeatures` Javadoc (configured-feature paths), `BCEnergyJeiPlugin`, `StirlingFuelCategory`, `EngineFuelJeiTypes`.
- **`.neoforge-ref/INDEX.txt`** lists `vanilla-26.2` and `vanilla-1.21.10`, which do not exist; the sync script and index disagree.
- **`BlueprintGuiRenderer`** is gated to 1.21.1 only and contains four `mulPose(Axis)` sites; dead on 26.3, but any future 26.3 port of that file needs the same fix.
- **`GpuBuffer`** became an interface and `Axis` stopped being a functional interface; BC has no subclassing or lambda use today.
- **Future subclasses** of `BaseEntityBlock` or `HorizontalDirectionalBlock` need a guarded `codec()` on every node below 26.3, or they fail only there. The block templates should carry the guard.

## Follow-ups after P15

Fix: a non-blending pipeline for the opaque cases so they stay out of the OIT phase.
