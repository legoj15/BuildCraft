# Простые одиночные теги
Каждый тег записывается в форме &lt;name arguments/&gt; — где name — это имя тега, а завершающий '/' означает, что тег сам по себе. Некоторые теги также имеют аргументы в виде «пар ключ-значение», например:
<guide_md>
"level"="42"
</guide_md>

## Новая страница
&lt;new_page/&gt; перенесёт содержимое после себя на следующую страницу.

## Ссылки
Такие ссылки ведут на другую страницу руководства, отображая заголовок и значок той страницы, на которую они указывают. Кроме того, можно сделать ссылку на стак предметов или оператор, даже если у них ещё нет страницы в руководстве.
Например:
<guide_md>
&lt;link to="buildcraftunofficial:config/json_insn_format"/&gt;
</guide_md>
получится:
<link to="buildcraftunofficial:config/json_insn_format"/>

или:
<guide_md>
&lt;link to="minecraft:iron_ingot" type="item_stack"/&gt;
</guide_md>
получится:
<link to="minecraft:iron_ingot" type="item_stack"/>

## Главы
&lt;chapter/&gt; создаёт «заголовок главы», который отображается в списке глав как цветной заголовок. У него есть один возможный аргумент: "level", который должен быть целым числом, большим или равным 0. Кроме того, для создания заголовков можно использовать несколько символов решётки (#) — так же, как в обычном формате markdown. Количество символов # (минус один) равно уровню заголовка.
Например:
<guide_md>
 ### Level 3 chapter
&lt;chapter name="Another level 3 chapter" level="2"/&gt;
</guide_md>
получится:
### Глава уровня 3
<chapter name="Другая глава уровня 3" level="2"/>

# Простые парные теги
Все они должны окружать некоторое содержимое: у них должны быть и открывающий тег &lt;italic&gt;, и закрывающий тег &lt;/italic&gt;
Все они влияют на текст, заключённый между открывающим и закрывающим тегами.

- <italic>курсив</italic>
- <bold>полужирный</bold>
- <underline>подчёркнутый</underline>
- <strikethrough>зачёркнутый</strikethrough>
- <red>красный</red>
- <black>чёрный</black>
- <dark_blue>тёмно-синий</dark_blue>
- <dark_green>тёмно-зелёный</dark_green>
- <dark_aqua>тёмно-голубой</dark_aqua>
- <dark_red>тёмно-красный</dark_red>
- <dark_purple>тёмно-фиолетовый</dark_purple>
- <gold>золотой</gold>
- <gray>серый</gray>
- <dark_gray>тёмно-серый</dark_gray>
- <blue>синий</blue>
- <green>зелёный</green> (зелёный)
- <aqua>голубой</aqua> (голубой)
- <light_purple>светло-фиолетовый</light_purple>
- <yellow>жёлтый</yellow> (жёлтый)
- <white>белый</white> (белый)

Не стоит использовать зелёный, голубой, жёлтый или белый, потому что эти цвета обычно очень трудно разглядеть на странице.

# Переключаемые теги
Все приведённые ниже теги зависят от настроек и могут быть включены или отключены игроком.

## Описание
Если установлен флажок «Показать описание [ ]», то всё содержимое тега &lt;no_lore&gt; будет скрыто, иначе будет скрыто всё содержимое тега &lt;lore&gt;.

Тег lore следует использовать для «внутриигровой» информации руководства, излагаемой с точки зрения игрока (как будто он сам активно исследует, как всё устроено). Обратный тег предназначен для более формального тона в духе Википедии, которым информация передаётся просто и по существу.

Эта опция включена по умолчанию в игре и всегда отключена при экспорте.

## Подсказки
Если установлен флажок «Показать подсказки [ ]», то всё содержимое тега &lt;no_hint&gt; будет скрыто, иначе будет скрыто всё содержимое тега &lt;hint&gt;.

Тег hint следует использовать для отображения дополнительных «подсказок» о том, для чего можно использовать описываемую вещь или как применять её в сочетании с другими блоками/предметами. По сути, это место для «рекомендуемых применений» разных вещей. (Разгадывать это самостоятельно — часть удовольствия, поэтому это не обязательно. Соответственно, эта опция отключена по умолчанию, но может переключаться в игре, а переключение при экспорте планируется.

## Подробности
Если параметр конфигурации "display.guideBookEnableDetail" установлен в "true", то всё содержимое тега &lt;no_detail&gt; будет скрыто, иначе будет скрыто всё содержимое тега &lt;detail&gt;.

Тег detail следует использовать для отображения всех чисел, участвующих в расчётах различных величин — скорости потока в трубах, скорости извлечения, частоты срабатывания и т. д.

Эта опция отключена по умолчанию, но может переключаться в игре, а переключение при экспорте планируется.

# Разное
## Рецепт (одиночный)
Этот тег показывает первый найденный рецепт для указанного стака предметов. Например:
<guide_md>
&lt;recipe stack="buildcraftunofficial:gear_stone"/&gt;
</guide_md>
<recipe stack="buildcraftunofficial:gear_stone"/>

Также можно закрепить конкретный рецепт по его идентификатору в реестре с помощью атрибута `id`. Используйте это, когда сопоставление по стаку предметов не может однозначно выбрать нужный рецепт — например, рецепт крафта, результат которого несёт компоненты данных (конкретный вариант гейта), не будет найден учитывающим компоненты сопоставлением по простому стаку предметов:
<guide_md>
&lt;recipe id="buildcraftunofficial:gate_basic"/&gt;
</guide_md>
<recipe id="buildcraftunofficial:gate_basic"/>

Добавьте `type="assembling"`, чтобы вместо этого закрепить рецепт Сборочного стола, найденный по его имени в реестре (а не по id рецепта крафта). Это позволяет странице чередовать рецепты крафта и сборки гейта в нужном порядке:
<guide_md>
&lt;recipe id="gate-and-IRON-NO_MODIFIER" type="assembling"/&gt;
</guide_md>
<recipe id="gate-and-IRON-NO_MODIFIER" type="assembling"/>

## Цикл рецептов
`recipe_cycle` сворачивает семейство почти одинаковых рецептов в одну панель, которая перебирает их синхронно — входы, результат и (для сборки) стоимость в MJ переключаются на следующий рецепт все вместе. Используйте его, чтобы свернуть, скажем, варианты И и ИЛИ гейта или целый набор рецептов замены в одну компактную анимированную запись вместо множества. Рецепты выбираются с помощью `match` — подстроки, которая проверяется по id каждого рецепта (или, с `type="assembling"`, по его имени в реестре). Ниже одна панель перебирает рецепты сборки железного гейта с вариантами И и ИЛИ (`match="-IRON-NO_MODIFIER"` выбирает оба):
<guide_md>
&lt;recipe_cycle type="assembling" match="-IRON-NO_MODIFIER"/&gt;
</guide_md>
<recipe_cycle type="assembling" match="-IRON-NO_MODIFIER"/>

## Рецепты
Этот тег показывает все рецепты для указанного стака предметов. Например:
<guide_md>
&lt;recipes stack="buildcraftunofficial:gear_wood"&gt;
</guide_md>
<recipes stack="buildcraftunofficial:gear_wood" chapter_level="2"/>

## Использование
Как и в случае с рецептами, этот тег показывает все способы применения указанного стака предметов. Например:
<guide_md>
&lt;usages stack="buildcraftunofficial:engine_redstone"&gt;
</guide_md>
<usages stack="buildcraftunofficial:engine_redstone" chapter_level="2"/>

## Рецепты и использование
Фактически этот тег объединяет два предыдущих в один, например:
<guide_md>
&lt;recipes_usages stack="buildcraftunofficial:pipe_structure"&gt;
</guide_md>
<recipes_usages stack="buildcraftunofficial:pipe_structure" chapter_level="2"/>

## Группа
Этот тег показывает группы, подходящие для указанного предмета, оператора и т. д.

## Изображения
Этот тег показывает изображение. У него есть 3 аргумента:
* src: Расположение источника изображения.
* width: Ширина, с которой будет показано изображение. По умолчанию равна ширине исходного изображения (однако это может быть не тем, что вам нужно)
* height: Высота, с которой будет показано изображение.

Например:
<guide_md>
&lt;image src="buildcraftunofficial:item/wrench" width="64" height="64"/&gt;
</guide_md>
<image src="buildcraftunofficial:item/wrench" width="64" height="64"/>
